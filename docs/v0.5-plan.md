# v0.5 — Image Gallery / Browser — Plan

Status: **DRAFT** — stub captured 2026-05-28, fleshed out 2026-07-07
after v0.4.0 (logbook) + v0.4.1 (stability) shipped.  Four scoping
decisions ratified with the operator (2026-07-07); see "Ratified

---

## Theme

A first-class image browser inside the app for received (and
optionally transmitted) SSTV images.  Today users leave the app for
Finder / Explorer to browse the RX folder.  v0.4 linked every logged
contact to its image; v0.5 is the visualization layer on top —
browse thumbnails, group by callsign / date / mode, jump straight to
the linked QSO, and re-send an image to the TX panel.

**Version & framing.**  This is **v0.5.0** — a new feature (new
window, menu, package), so it earns a minor bump, keeping faith with
the pattern v0.4.1 set (a patch = fixes only).  But it is the
*completion of the v0.4 logging workflow*, and the release notes
should say so: *"v0.5.0 — Image Gallery: browse, group, and re-send
the images behind every contact."*  Users get the continuity story in
words; the version number stays honest about what changed.

## Why now

v0.4 shipped the logbook and its data model; v0.4.1 closed the whole
post-release stability audit (19 findings).  The foundation is
solid and the QSO↔image link the gallery needs already exists.  The
RX panel's thumbnail strip (`ImageGalleryWidget`) has proven the
core interaction; v0.5 is "expand that strip into a real browser."

## Codebase foundation (already there)

Confirmed via 2026-07-07 survey:

- `src/open_sstv/ui/image_gallery.py` — `ImageGalleryWidget`: a
  `QListView` in `IconMode` with tmpdir-backed thumbnails, a
  context menu, and mode coercion.  The v0.5 window is a scaled-up,
  persistent sibling of this widget; much is directly reusable.
- `src/open_sstv/logbook/model.py` — `QSO.image_path` /
  `QSO.audio_path` store file references (not blobs), exactly the
  link the gallery keys off.
- `src/open_sstv/config/schema.py` — `images_save_dir` is the single
  save directory for **both** RX (`auto_save`) and TX (`autosave_tx`,
  opt-in since v0.2.8) images.  `autosave_filename_pattern` defaults
  to `%d_%t_%m` → e.g. `2026-04-17_213512_Scottie-S1.png`, so a file
  **without** a QSO row still yields date / time / mode by parsing
  the name.
- `src/open_sstv/ui/utils.py` — `pil_to_pixmap` / `pil_to_qimage`
  thumbnail helpers.
- `src/open_sstv/ui/logbook_dialog.py` — the detached-window +
  filter-bar + detail-panel patterns to mirror (debounced filters,
  local-day date bounds, missing-image indicator — all v0.4.1-audited).
- `platformdirs.user_cache_dir("open_sstv")` — the established home
  for caches (`update_checker`), so the persistent thumbnail cache
  lands there.

**Gaps to fill:** no reverse image→QSO lookup exists on
`LogbookStore` (add one small query); no persistent thumbnail cache
(new); the gallery-item metadata patch from `future_work.md`
("decode timestamp + autosave path") folds in here rather than as a
separate v0.4.x patch.

## Design decisions

### 1. The gallery is a filesystem × logbook *join*

This is the load-bearing model.  A **gallery item is a file on
disk**, optionally *enriched* by a matching QSO record.  Four cases,
all handled:

| On disk? | QSO row? | Gallery shows |
|---|---|---|
| yes | yes (matched on `image_path`) | thumbnail + full QSO metadata, click → Logbook row |
| yes | no | thumbnail + date/time/mode parsed from filename; no callsign |
| no | yes (`image_path` dangling) | *not shown* — the file is the item; the Logbook already flags these with its missing-image indicator |
| no | no | n/a |

So the gallery **scans `images_save_dir`** for image files and
**left-joins** the logbook by path.  This correctly covers
auto-saved images the user never logged (dialog dismissed), logged
QSOs whose image is present, and everything in between — without
forcing every file to have a QSO or every QSO to have a live file.

### 2. Reverse lookup: in-memory index, built on open

At the ratified ≤10k scale, the gallery loads all QSOs once via
`store.list_qsos()` on window open and builds a
`{resolved_image_path: QSO}` dict.  No schema change, no per-item
query.  (A `LogbookStore.find_by_image_path()` is added too for the
single-item refresh-after-edit path, but the bulk join is the dict.)

### 3. Standalone window

`GalleryDialog` — its own detached `QDialog`, opened via **Tools →
Gallery…** (Cmd/Ctrl+G), mirroring the Logbook window.  Keeps the
Logbook a focused table and the Gallery a focused icon grid; both
open side by side.  Clicking a QSO's image in the Logbook focuses
the Gallery on that item, and the Gallery's "→ QSO" focuses the
Logbook on that row — two windows, one data source.

### 4. TX images: surface the existing `autosave_tx` output

No new retention behavior and no new privacy surface.  The gallery
shows whatever is in `images_save_dir` — which already includes TX
images **only when the operator opted into `autosave_tx`**.  RX
(always, when `auto_save` on, plus v0.4 log-time capture writes) +
opt-in TX.  Direction is read from the linked QSO, or inferred from
context when unlinked.

### 5. Thumbnails: persistent disk cache + in-memory LRU

At ≤10k images, generate thumbnails on demand and cache them under
`user_cache_dir("open_sstv")/thumbnails/`, keyed by a hash of
`(absolute_path, mtime, size)` so a moved/edited file re-renders and
a reopened gallery is instant.  An in-memory LRU (a few hundred
`QPixmap`s) covers the visible viewport during a scroll.  Plain
`QListView` in `IconMode` — no virtualization needed at this scale.

### 6. Grouping / sort without a section-header rabbit hole

`QListView` has no native section headers.  For v0.5 "standard,"
grouping is a **sort key** (by date / callsign / mode) selected from
a combo, with a lightweight non-selectable header row inserted
between groups in the flat model (the same trick the template
gallery uses for role separators).  No custom tree/delegate — keeps
the grid simple and fast.

## Scope (v0.5.0) — "Standard browser" (ratified)

### New package: `src/open_sstv/gallery/`

| File | Purpose |
|---|---|
| `__init__.py` | Public API |
| `scanner.py` | Scan `images_save_dir` for image files; parse `%d_%t_%m` filenames for date/time/mode; return `GalleryItem` records. Pure, no Qt. |

### Logbook store

| File | Change |
|---|---|
| `logbook/store.py` | `find_by_image_path(path) -> QSO \| None` — single-item reverse lookup (`image_path` already stored POSIX-normalized). |

### Operations

- **Delete** — confirm; remove the image file; if a QSO links it,
  clear that row's `image_path` (never delete the QSO — the mirror of
  the Logbook's "delete row keeps file").
- **Export…** — copy the file to a user-chosen location (never move).
- **Re-send to TX** — load the image into the TX panel as a new
  outgoing image (reuses `TxPanel.set_rx_image` / the existing
  `rx_image_selected` plumbing).

### Config

| File | Change |
|---|---|
| `config/schema.py` | `gallery_extra_dirs: list[str] = []` — optional additional folders to scan beyond `images_save_dir` (advanced; no UI in v0.5, TOML-only, mirrors `logbook_db_path`). |

## Explicitly out of scope (deferred)

| Item | Defer to | Why |
|---|---|---|
| Free-text search across QSO notes | v0.5.x / v0.6 | The "full asset manager" tier; standard browser ships first. |
| Tag / star / favorites | v0.5.x | Nice-to-have; needs its own persisted state. |
| Batch operations (multi-select delete/export) | v0.5.x | Single-item first; multi-select is additive. |
| QSO-grouped "all images from this contact" view | v0.5.x | Group-by-callsign sort covers most of it without the join complexity. |
| Dedicated always-on TX-history dir | never (use `autosave_tx`) | Retention stays opt-in; no new privacy surface. |
| Virtualized scrolling / thumbnail DB | if scale demands | ≤10k target doesn't need it; revisit only if a user reports slowness. |
| EXIF / embedded metadata | never | Filename `%d_%t_%m` + QSO link already carry what we need. |

## Release cadence

Branch `v0.5-gallery` off main.  Three sequential PRs, each through
the 9-cell matrix gate:

1. **PR #1 — Gallery data layer.**  `gallery/` package (scanner,
   model, thumbnail_cache, index) + `find_by_image_path` + their
   tests.  No UI.  Zero user-visible change.
2. **PR #2 — Gallery window.**  `GalleryDialog` + Tools menu +
   Cmd/Ctrl+G + filter/sort/group + detail sidebar + pytest-qt
   tests.  Read-only browsing.
3. **PR #3 — Operations + cross-links + release.**  Delete / Export /
   Re-send, Logbook↔Gallery focus wiring, docs, screenshot, banner
   bump, CHANGELOG, version bump.  Tag `v0.5.0` from this merge.

Same flow the v0.4 releases proved: squash-merge, matrix-gated, tag
triggers the binary build + GitHub release + site update.

## Acceptance criteria (verification)

1. Tools → Gallery… (Cmd/Ctrl+G) opens a grid of thumbnails from
   `images_save_dir`.
2. An image with a logged QSO shows callsign/mode/freq/time in the
   sidebar; "→ QSO" opens the Logbook focused on that row.
3. An image with no QSO still shows date + mode parsed from its
   filename.
4. Group/sort by date / callsign / mode reorders the grid; callsign
   grouping uses the QSO link.
5. Filter by callsign / mode / date range narrows the grid (debounced).
6. Delete → confirm → file gone, and if it was linked the QSO row
   survives with `image_path` cleared.
7. Export → copies the file; original untouched.
8. Re-send → the image loads into the TX panel ready to transmit.
9. Reopening the gallery is instant (thumbnail cache hit); editing a
   file off-app re-renders its thumbnail (mtime key).
10. Fast and smooth at 10k images.
11. 9-cell CI matrix green for every intermediate PR.

## Ratified decisions (2026-07-07)

Worked through with the operator; all four locked for v0.5.0:

1. **Window:** standalone `GalleryDialog` via Tools → Gallery…
   (Cmd/Ctrl+G), paired with the Logbook window.
2. **TX images:** surface the existing opt-in `autosave_tx` output —
   no new retention behavior.
3. **Scope:** "Standard browser" — thumbnails + group/sort +
   preview/metadata + → QSO + delete/export/re-send.  Search, tags,
   batch ops, and the QSO-grouped view deferred.
4. **Scale:** target ≤10k images — on-demand thumbnails with a
   persistent disk cache + in-memory LRU; plain `QListView`, no
   virtualization.
