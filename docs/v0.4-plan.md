## Theme

Every SSTV contact you make or hear gets captured — image, mode,
frequency, time, callsign, RSV, notes — and exported as ADIF for
interop with HRD, N1MM, LoTW, eQSL, Club Log, QRZ.com.

SSTV apps that don't do this (MMSSTV historically) leave operators
copy-pasting into a separate logger.  Open-SSTV can do better by
making capture the default path and ADIF export a one-click action.

## Why now

v0.3.x closed the audit top-to-bottom and shipped a diagnostics
pipeline that proved its worth within hours of release (v0.3.21
diagnostics zip → v0.3.22 root-cause fix).  The product is stable
enough that the next push should be **user-visible value**, not more
hygiene.  Logbook is the single largest gap between Open-SSTV and the
loggers ham operators already expect.

## Design decisions

### 1. Storage: SQLite (stdlib `sqlite3`)

**Source of truth = SQLite database at `user_data_dir/logbook.db`.**
ADIF is the *interchange* format, not the *storage* format.

Why:

- Right shape for "thousands of QSOs accumulated over years."
- Indexable for fast filter/search (by callsign, date range, mode).
- Stdlib `sqlite3` — no new pip dependency.
- Easy to ADIF-export; harder to query an ever-growing append-only
  ADI file.
- Schema versioning is straightforward (`PRAGMA user_version`).

Beats TOML/JSON for any operator who logs more than a few dozen QSOs.

### 2. UI surface: separate `QDialog` window via Tools menu

**Logbook lives in its own window, not as a tab in the main UI.**
Opened via Tools → Logbook… or Cmd/Ctrl+L.

Why:

- Main window's horizontal splitter (TX panel / RX panel) is
  deliberate — the audit explicitly noted it.  Tab-ifying breaks
  the live operating UX.
- Separate window matches established ham-app conventions: MMSSTV,
  JS8Call, fldigi, WSJT-X all use detached logbook windows.
- Can be sized/positioned independently per-OS without fighting
  the operating panes.
- Easy to alt-tab between rig control and logbook on a single
  monitor; trivially side-by-side on dual.

### 3. Capture flow: "draft on completion, user confirms"

**Default:** at TX/RX completion, open a `LogQsoDialog` with
everything we know auto-filled; user fills in callsign + signal
report + notes and saves.

**Opt-out:** `auto_log_qsos: bool = False` config flag.  When True,
the draft is written silently and the user edits it later from the
Logbook window.

Why default to modal:

- Hands-on operators benefit from immediate capture while the
  contact is fresh.
- Silent auto-log invites pile-up of empty-callsign drafts the user
  forgets to fill in.
- Modal can be dismissed with Esc → no row written, so there's no
  cost to false positives (e.g. a noise-triggered RX completion).

### 4. Signal report: RSV (SSTV convention), not RST

`rsv_sent` and `rsv_received` are 3-digit strings.  ADIF export
writes them to `RST_SENT` / `RST_RCVD` since ADIF predates SSTV's
RSV convention; comment field can note "SSTV RSV format" if needed.

### 5. Image association: store paths, not blobs

Image lives where it always did (`images_save_dir`); logbook row
stores the path.  If the user moves/deletes the image outside the
app, the row remains with a "missing image" indicator.  We don't
take ownership of user files.

## Scope (v0.4.0)

### New package: `src/open_sstv/logbook/`

| File | Purpose |
|---|---|
| `__init__.py` | Public API: `LogbookStore`, `QSO`, `export_adif`, `import_adif` |
| `model.py` | `QSO` dataclass: `id`, `direction` (RX/TX), `callsign`, `time_utc`, `mode`, `frequency_hz`, `rsv_sent`, `rsv_received`, `name`, `qth`, `grid`, `comment`, `image_path`, `audio_path`, `created_at`, `updated_at` |
| `store.py` | SQLite manager.  Tables: `qsos` (1 row per contact), `qso_images` (1-to-many for multi-image QSOs).  Schema versioned via `PRAGMA user_version`.  CRUD + filtered queries. |
| `adif.py` | Pure-Python ADIF 3.1.5 reader/writer.  `to_adif(list[QSO]) -> str`, `from_adif(str) -> list[QSO]`.  Roundtrip-clean. |
| `coordinator.py` | `LogbookCoordinator` — listens to RX/TX completion signals, builds drafts, hands to UI or auto-saves per config. |

## Release cadence

Branch `v0.4-logbook` off main.  Land in **four sequential PRs** rather
than one mega-PR.  Each through the 9-cell matrix gate; easier to
review and easier to revert.

1. **PR #1 — Data layer.**  `model.py` + `store.py` + `adif.py` + their
   tests.  No UI.  Zero user-visible change.
2. **PR #2 — Capture flow.**  `LogbookCoordinator` + worker signal
   payload additions.  Still no UI window — drafts go straight to
   SQLite (essentially `auto_log_qsos=True` is the only available
   path at this point).
3. **PR #3 — Main UI.**  `LogbookDialog` + `LogQsoDialog` + menu entry
   + `auto_log_qsos` config + tests.  Capture flow now has a
   non-silent path.
4. **PR #4 — Polish + release.**  Settings logging tab, docs, README
   blurb, screenshot, banner bump, CHANGELOG, pyproject version bump.
   Tag `v0.4.0` from this PR's merge.

Each PR is mergeable in isolation; v0.4.0 only ships when all four
land and a fresh PyInstaller binary has been smoke-tested on all
three OSes.

## Acceptance criteria (verification)

1. TX a transmission → log dialog appears with mode/time/freq
   auto-filled → enter callsign + RSV → Save → row appears in
   Logbook window.
2. RX a transmission → log dialog appears with
   mode/time/freq/image auto-filled → enter callsign → Save →
   row appears.
3. Export ADIF → import into N1MM or HRD → all fields land in
   correct columns.
4. Import an ADIF from another logger → entries appear; dedupe
   on `(callsign, time_utc, mode)` skips duplicates.
5. Delete a QSO → confirmation → row gone, underlying image file
   untouched.
6. Quit and relaunch app → logbook contents persist.
7. `auto_log_qsos=True` → no dialog, draft QSO appears in Logbook
   window with empty callsign for later edit.
8. Diagnostics zip: default off for `logbook.db`; checkbox in
   export dialog includes it when ticked.
9. 9-cell CI matrix green for every intermediate PR.

## Open questions (sanity-check items)

These are the design decisions I want to ratify with the operator
before starting PR #1:

1. **SQLite as source of truth + ADIF as export format** vs.
   ADIF-native append-only file.
2. **Separate Logbook window via Tools menu** vs. tab-ification of the
   main window.
3. **Draft-on-completion modal dialog default** vs. silent auto-log
   default.

A fourth implicit question: do we want **FSKID decode in v0.4.0**, or
is "manual callsign entry only" acceptable for the initial release?
FSKID is the single largest UX win after the logbook itself, but it's
a multi-day DSP feature that risks blowing the v0.4 scope.
